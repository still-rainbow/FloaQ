# 조난 신고 (DSC · AIS)

Pi 가 직접 발신하는 조난 신고의 규격과 구현을 정리한다.
LoRa 는 [lora.md](lora.md), MQTT 는 [mqtt.md](mqtt.md), 전체 구성은
[architecture.md](architecture.md).

관련 티켓: floaq-175 (신고 UDP 발신 · AIS-MOB/AIS-SART/DSC)

> 🔴 **이 구현은 시뮬레이션이다.**
> 실제 전파가 나가지 않으며 형식 승인된 GMDSS 장비를 대신할 수 없다.
> 이 비트열을 실제 조난 주파수(VHF Ch70 156.525MHz, AIS 161.975/162.025MHz,
> MF 2187.5kHz)로 변조해 송신하면 불법이고 실제 수색구조 자원이 출동한다.
> UDP 로 보내 항해 소프트웨어에서 확인하는 용도까지만 쓴다.

---

## 1. 계층

규격이 정본이고 NMEA 는 그 출력 형식 하나다. 반대가 아니다 — 특정 수신
소프트웨어에 맞추기 시작하면 규격에서 멀어진다.

```
floaq/protocols/dsc.py   ITU-R M.493    심볼 프레임      ← 정본
floaq/protocols/ais.py   ITU-R M.1371   메시지 + 링크    ← 정본
floaq/adapters/nmea.py   NMEA 0183      $CDDSC · !AIVDM  ← 직렬화
floaq/adapters/report.py UDP 송수신 · 채널별 주기
```

`protocols/` 는 소켓도 NMEA 도 모른다. 시험으로 강제한다:

```bash
grep -rn "socket\|serial\|paho" iot/pi/floaq/protocols/     # 비어 있어야 한다
```

### 왜 NMEA 를 거치는가

무선에 실리는 것은 심볼과 비트다. 그러나 무전기와 플로터 사이는 NMEA 로 말한다.
실제 DSC 무전기가 조난 호출을 수신하면 `$CDDSC` 로 플로터에 넘긴다. 우리가 그
자리에 서면 항해 소프트웨어가 우리 신고를 그대로 알아본다 — 자체 뷰어를 만드는
것보다 검증력이 높다.

## 2. 채널 세 개

| 채널 | MMSI | 주기 | 중지 |
|---|---|---|---|
| `AIS_MOB` | `972` + 6자리 | 1분 8회 + 4분마다 문구 | 수동만 |
| `AIS_SART` | `970` + 6자리 | 동일 | 수동만 |
| `DSC` | 선박 MMSI | 연속 5회, 3½~4½분 무작위 간격 | **확인응답 시 자동** |

🔴 **채널별 분기를 한 루프에 욱여넣지 않는다.** DSC 는 확인응답으로 멈추고 AIS 둘은
수동으로만 멈춘다. `database/pi.sql` 이 같은 규칙을 DB 에서 한 번 더 막는다:

```sql
CHECK (acked_at IS NULL OR channel = 'DSC')
```

## 3. DSC — ITU-R M.493

### 3.1 심볼 (§1.1)

10비트. 앞 7비트가 정보, 뒤 3비트가 체크다.

```
체크 3비트 = 7개 정보비트 중 B 요소(0)의 개수
정보비트는 LSB 먼저, 체크비트는 MSB 먼저 송신
```

🔴 **송신 순서가 정보와 체크에서 서로 반대다.** 한쪽 기준으로 통일해 짜면 전부 틀린다.

### 3.2 시간분산 (§1.2)

phasing 을 뺀 모든 문자를 두 번 보낸다. 첫 송신(DX) 뒤 **다른 문자 4개**가 지난 뒤
다시 보낸다(RX). 짝수 위치가 DX, 홀수가 RX이고 위치 `p` 의 DX 가 `p+5` 에서 RX 로 나온다.

VHF 에서 그 간격이 33⅓ms, HF/MF 는 400ms.

### 3.3 조난 경보 구성 (Table 4.1)

```
점 패턴          VHF 20비트 / HF·MF 조난 200비트   (§3.4)
phasing         DX 125×6,  RX 111→104             (§3.2)
형식지정자 112   (2개 동일)                         (§4.1.1)
자기식별         MMSI 5심볼                         (§5.2)
조난성격         1심볼                              (§8.1.1)
조난좌표         5심볼                              (§8.1.2)
시각             2심볼 UTC                          (§8.1.3)
후속통신         1심볼                              (§8.1.4)
EOS 127         DX 3회 / RX 1회                    (§9)
ECC             DX·RX 각 1회                       (§10)
```

실제 출력 (52심볼 = 520비트, 점 패턴 제외):

```
[125,111,125,110,125,109,125,108,125,107,125,106, 112,105, 112,104,
  44,112,  1,112, 23, 44, 45,  1, 60, 23, 110, 45, ... ]
```

⚠ 조난 경보에는 **주소도 카테고리도 없다** (§5.1, §6.2). 전 국에 암묵적으로 간다.

⚠ EOS 는 **127** 이다. 117(Ack RQ)은 개별·자동 호출 전용이라 쓸 수 없다 (§9.1).

### 3.4 좌표 (§8.1.2)

10자리 `Q DD MM DDD MM` — 사분면 1 + 위도 도분 4 + 경도 도분 5.

```
사분면   0=NE  1=NW  2=SE  3=SW
```

⚠ 분이 **정수**라 해상도가 1분 = 약 1.85km 다. 규격 자체의 한계로 DSC 로는 더
정밀하게 못 보낸다. NMEA 로 내보낼 때 `$CDDSE` 확장이 1/10000 분까지 보정한다.

⚠ 분을 **내림한다.** 반올림하면 59.7분이 60분이 되어 도가 하나 밀리고 60해리가 틀어진다.

좌표를 못 넣으면 9 를 열 번 (§8.1.2.4). 시각을 못 넣으면 `8888` (§8.1.3.3).

### 3.5 ECC (§10.2)

정보문자 7비트의 **짝수 수직 패리티**(= XOR).

🔴 **형식지정자와 EOS 는 각각 하나씩만 넣는다.** 형식지정자는 DX 에 두 번 실리지만
ECC 에는 한 번만 반영한다. 두 번 넣으면 XOR 이라 서로 상쇄되어 형식지정자가 아예
빠진 것과 같아진다 — 실제로 이 버그를 냈다가 잡았다.

### 3.6 조난 성격 (Table 3)

```
100 화재·폭발     104 전복 위험    108 퇴선
101 침수          105 침몰         109 해적·무장강도
102 충돌          106 동력상실·표류  110 익수자
103 좌초          107 미지정 조난   112 EPIRB 발신
```

⚠ **111 은 이 표에 없다.** EPIRB 는 112 다.
`database/pi.sql` 의 `CHECK (report_dsc BETWEEN 100 AND 111)` 은 111 을 허용하고 112 를
막는다 — 규격과 어긋난다. Pi 가 EPIRB 를 발신하지 않아 지금은 무해하나 스키마를
손볼 때 같이 고칠 것.

### 3.7 반복 (M.541 §3.1.3.1)

```
한 번의 호출 시도 = 연속 5회
다음 시도까지     = 3½~4½분 사이 무작위
```

🔴 **무작위인 이유가 핵심이다.** 규격 원문: "호출 충돌과 **확인응답 유실**을 피하기
위해… 무작위로 도착하는 확인응답이 재전송에 막히지 않고 수신되게 한다."

확인응답은 해안국 운용자가 **수동으로** 보내므로(M.541 §3.3) 언제 올지 모른다.
고정 간격이면 재전송이 확인응답 수신 창을 매번 같은 자리에서 막는다.

⚠ 반복마다 새로 뽑아야 한다. 한 번 뽑아 재사용하면 고정 간격과 같아진다.

⚠ 확장 메시지(DSE)는 **연속 5회 중 마지막 뒤에 한 번만** (M.493 §11.4.1).

## 4. 조난 확인응답 — 어떻게 오는가

### 4.1 물리 경로

```
1. 우리 배 DSC 무전기 → VHF Ch70 (156.525MHz) 조난 경보 송신
2. 해안국이 Ch70 상시 청취 중 수신            ← 해경 상황실 / VTS
3. 해안국 운용자가 수동으로 확인응답 송신
4. 우리 배 무전기가 Ch70 수신, 심볼 복호
5. 조난선 MMSI 가 우리 것인지 대조
6. 무전기가 NMEA 포트로 $CDDSC 출력           ← 우리 코드는 여기부터
7. Pi 가 시리얼로 읽음
```

무전기가 무선을 벗겨 NMEA 로 건네준다. 우리 코드는 6번 이후만 본다.
그래서 `listen()` 을 UDP 로 짜두고, 실물 무전기가 생기면 그 메서드만 갈아끼운다.

### 4.2 누가 보내는가 — 해안국만

M.541 §3.3:

> 조난 호출은 보통 **해안국만** DSC 확인응답으로 응답한다.
> 선박은 해안국이 응답할 시간을 주도록 확인응답을 지연해야 한다.

§3.3.4:

> 선박은 조난 호출을 받으면 무선전화 주파수에서 청취하고 **무선전화로** 응답한다.

즉 주변 어선이 우리 신고를 받아도 DSC 확인응답을 보내지 않는다.
그래서 수신 판정에 세 조건을 모두 건다.

### 4.3 확인응답 구성 (Table 4.2, VHF RT)

```
형식지정자 116 (전선박) · 카테고리 112 (조난) · 자기식별 5 (해안국 MMSI)
· 텔레커맨드 110 (distress acknowledgement) · 조난선 MMSI 5
· 조난성격 1 · 조난좌표 5 · 시각 2 · 후속통신 100 · EOS 127 · ECC
```

⚠ 조난 **경보**와 배치가 다르다. 경보에는 카테고리도 텔레커맨드도 없다.
확인응답에는 둘 다 있고 **MMSI 가 둘** 실린다 — 자기식별(해안국)과 조난선.
순서를 바꾸면 엉뚱한 배를 지목한다.

⚠ 형식지정자가 120(개별)이 아니라 **116(전선박)** 이다. 그 구역 모두가 들어야 한다.

⚠ EOS 는 122(Ack BQ)가 아니라 **127** 이다. Table 4.2 가 그렇게 적고 있다.
122 는 distress relay acknowledgement 쪽이다 (§9.2).

### 4.4 우리 것인지 가르는 법

```python
format_specifier == 116 and category == 112 and telecommand1 == 110
and distress_mmsi == 우리 MMSI
```

**필드 2 는 보낸 쪽(해안국), 필드 8 이 조난선**이다. 둘이 다르다.

거르는 것 네 가지 (전부 시험 있음):

| 거르는 대상 | 왜 |
|---|---|
| 체크섬 불일치 | 깨진 문장 |
| 조난 경보(112) | 확인응답으로 오인하면 쏘자마자 자기가 멈춘다 |
| 남의 배 확인응답 | 같은 망에 흐른다. 조난선 MMSI 로 가른다 |
| 자기가 쏜 것 되받기 | 브로드캐스트면 흔하다 |

### 4.5 받으면 무엇이 멈추는가

**DSC 만.** M.541 §3.3.5 가 자동 반복을 자동 종료하라고 한다.

🔴 **AIS 두 채널은 계속 간다.** AIS 는 단방향 브로드캐스트라 확인응답이 없고,
신고 접수는 구조 완료가 아니다. 여기서 AIS 까지 멈추면 표류 중인 익수자를 놓친다.

### 4.6 아직 없는 것

확인응답이 **영영 안 올 수도 있다.** 운용자가 DSC 대신 Ch16 무선전화로 응답하는
경우가 그렇다(§3.3.4 가 선박에게 그렇게 하라고 한다). 그러면 구조는 진행 중인데
DSC 확인응답은 없다.

M.541 §3.1.3.1 은 **자동 반복을 수동으로 무시할 수 있어야** 한다고 적는다.
지금 키오스크 명령에 그 수단이 없다 — `cancel`·`report_now`·`report_manual`·
`rescue`·`close` 뿐이다. `미정`⚠ TODO(IoT)

## 5. AIS — ITU-R M.1371

### 5.1 조난 장치에 별도 메시지가 없다

AIS-SART·MOB·EPIRB 는 일반 위치보고(Message 1)를 쓰되 **항행상태 14** 를 넣고,
MMSI 접두로 장치 종류를 구분하며, Message 14 로 규정 문구를 함께 보낸다.

```
970MIDXXX  SART    "SART ACTIVE" / "SART TEST"
972XXXXXX  MOB     "MOB ACTIVE"  / "MOB TEST"
974XXXXXX  EPIRB
```

🔴 항행상태 14 가 없으면 수신기가 **일반 선박으로 그린다.**

### 5.2 Message 1 비트 배치 (Table 45)

```
0-5     6   메시지 종류 = 1
6-7     2   반복 지시자
8-37    30  MMSI
38-41   4   항행 상태          ← 14
42-49   8   선회율 (부호 있음)
50-59   10  대지속력 0.1노트
60      1   위치 정확도
61-88   28  경도  1/10000 분   ← 경도가 먼저, 28비트
89-115  27  위도  1/10000 분   ← 위도가 나중, 27비트
116-127 12  대지침로 0.1도
128-136 9   진침수
137-142 6   타임스탬프 UTC 초
143-144 2   특수조작 지시자
145-147 3   예비
148     1   RAIM
149-167 19  무선 상태
```

총 168비트. AIVDM 한 문장에 정확히 들어간다(fill 0).

⚠ **경도가 위도보다 앞이고 비트 폭도 하나 더 크다.** 순서나 폭을 바꾸면 값이
조용히 잘린다.

⚠ 좌표는 **1/10000 분** 단위 2의 보수다. 십진도 × 600000.
2의 보수를 틀리면 남위·서경이 지구 반대편에 찍힌다.

### 5.3 Message 14 (Table 55)

```
0-5    6   메시지 종류 = 14
6-7    2   반복 지시자
8-37   30  MMSI
38-39  2   예비
40-    6n  안전 관련 문구 (6비트 문자, 최대 161자)
```

문구가 규격으로 정해져 있다. 임의로 바꾸면 수신기가 MOB 로 인식하지 않는다.

### 5.4 송신 주기 (IEC 61097-14)

```
위치보고     1분에 8회 버스트
Message 14  4분마다 한 번, 위치보고 하나를 대체
```

### 5.5 링크 계층 (Annex 2 §3.2)

```
훈련열(24비트 0/1 교번) · 시작플래그 0x7E · [데이터 + FCS] 스터핑 · 종료플래그 · 버퍼
```

- **비트 스터핑** — 1 이 다섯 번 연속되면 0 을 끼운다. 플래그와 구별하기 위함
- **플래그는 스터핑하지 않는다** — 1 이 여섯 개지만 그래야 경계로 쓸 수 있다
- **FCS** — CRC-ITU-T 16비트, 초기값 전부 1 (ISO/IEC 3309). **LSB 먼저** 실린다
- **NRZI** — 🔴 **0 에서 레벨이 바뀌고 1 에서 유지된다.** 직관과 반대다

⚠ AIVDM 은 **메시지 비트만** 싣는다. CRC·스터핑·NRZI 는 수신기가 이미 벗겨냈다.
링크 계층은 규격 완결성과 시험용으로 `protocols/ais.LinkFrame` 에 둔다.

## 6. NMEA 0183 직렬화

### 6.1 숫자 필드 = 심볼 − 100

```
형식지정자  112 조난 -> 12    116 전선박 -> 16    120 개별 -> 20    102 지역 -> 02
카테고리    112 조난 -> 12
조난성격    110 익수자 -> 10
후속통신    100 F3E/G3E TP -> 00
```

🔴 `pi_accident.report_dsc` 는 심볼값(110)을 담는다. **문장에 그대로 넣으면 안 된다.**

### 6.2 $CDDSC 필드 순서 (IEC 61162-1)

```
1 형식지정자  2 주소/발신 MMSI(10자리)  3 카테고리  4 성격 또는 telecommand1
5 telecommand2  6 위치 또는 채널  7 시각  8 조난선 MMSI(중계)
9 성격(중계)  10 확인응답  11 확장지시자
```

⚠ **필드 4 는 형식에 따라 성격이거나 텔레커맨드다.** 전선박+조난이면 텔레커맨드이고
성격은 필드 9 에 있다. 한쪽으로만 읽으면 확인응답을 놓친다.

⚠ MMSI 는 **10자리**로 내보낸다. M.493 §5.2 의 (X9,0) 규칙이다. 수신 측이 앞 9자리를 취한다.

### 7.2 OpenCPN 에서 확인

```
Options > Connections > Add Connection > Network
Protocol   UDP
Address    0.0.0.0

```

10110 은 NMEA 0183 over TCP/UDP 에 IETF 가 할당한 포트다.

AIS 표적 목록에 뜬다. DSC 조난 표적은 목록 맨 위에 고정된다.

### 7.3 해안국 확인응답

```powershell
python tools\coastguard_ack.py --watch --listen-port 10113
```

조난 경보를 기다렸다 Table 4.2 확인응답을 되쏜다. **DSC 만 멈추고 AIS 는 계속
가는 것**을 눈으로 볼 수 있다.

⚠ 송수신 포트를 같게 두면 소켓 둘이 같은 포트에 바인드되어 확인응답이 엉뚱한
쪽으로 간다. `--listen-port` 로 분리할 것.

## 8. 미정

| 항목 | 내용 |
|---|---|
| MMSI 발급 | 선박 MMSI 가 없다. 지금은 `440123456` 예시값. 해양경찰청 등록 사항 |
| 조난 장치 MMSI | `972`/`970` + 선박 MMSI 뒤 6자리로 임시 파생. 실제 발급 절차 없음 |
| VHF DSC 무전기 | 없다. 확인응답 경로가 물리적으로 없어 UDP 가 대신한다 |
| 수동 확인응답 표시 | 무전으로 접수 확인 시 반복을 멈출 키오스크 명령이 없다 |
| `report_dsc` CHECK | 111 허용 / 112 차단. 규격과 어긋난다 |
| 해경 운용 정책 | 자동 응답인지 수동인지, 응답까지 실제 소요 시간 |
