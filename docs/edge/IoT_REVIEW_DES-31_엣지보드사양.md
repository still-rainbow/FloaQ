DES-31은 ① 보드 사양 ② 모델 경량화·양자화 ③ 추론 프레임워크로 구성된다. 이 문서는 **①만** 다룬다. ②·③은 §5 벤치마크 결과를 입력으로 받는다.

## 1. 추론 보드 배치 결정

**추론은 Jetson 단독. Pi 5에는 추론 워크로드를 배치하지 않는다.**

Pi 5는 안전 상태머신의 실시간성을 보장하는 보드다. 추론이 CPU를 점유하면 `SAFE→AIMING→ARMED→READY→RELEASED` 전이 지연이 비결정적으로 늘어난다(상태 정의는 [DES-38](IoT_REVIEW_DES-38_각도제어구조.md)이 정본). 안전 판단 경로와 추론 경로를 물리적으로 분리한다.

| 보드 | 역할 | 추론 부하 |
|---|---|---|
| Jetson Orin Nano Super | 영상 수집·안정화, 탐지, 추적, 스테레오 거리·방위, 발사 요청 생성 | 전량 |
| Raspberry Pi 5 | 센서 수집, 안전 상태머신, 서보 제어, LoRa 수신, MQTT 브로커, SQLite, 서버 동기화 | 없음 |

보드 분리만으로 실시간성이 보장되지는 않는다. 통신 지연·단절 시험이 필요하다(§5 #9).

## 3. 설계 제약과 대응

우선순위 순.

### C-1. DLA 없음 — 추론 경로가 GPU 하나뿐

Orin Nano에는 DLA가 없다(Orin NX·AGX와 다른 점). 탐지·추적·스테레오를 분산할 수 없으므로 전부 단일 GPU를 시분할한다.

유휴 상태에서 `NVDEC / NVJPG / VIC`가 모두 off다. 영상 디코드·JPEG 인코드·리사이즈·색변환을 이 고정 기능 엔진으로 내려 GPU를 추론 전용으로 비운다. 실질적으로 확보 가능한 유일한 여유다. 스테레오 매칭을 GPU에 둘지 CPU(StereoSGBM)로 둘지는 GPU 점유율 실측 후 결정한다.

### C-2. 8 GB 통합 메모리 — 유휴에 이미 2.6 GB 점유

CPU와 GPU가 같은 물리 메모리를 쓰는데 데스크톱 GUI가 상주한다. snap에 `chromium` 2개 리비전, `gnome-46-2404`, `cups` 2개, `mesa-2404`, `gtk-common-themes`가 마운트돼 있다.

- 대응: `sudo systemctl set-default multi-user.target`으로 헤드리스 전환, `chromium`·GNOME snap 제거. 전후 `free -h`와 `lfb`를 기록한다.
- `lfb 3x4MB`를 단편화 근거로 단정하지 않는다. JetPack에서 lfb 블록 단위가 4MB로 고정 보고되는 경우가 있다. 실제 판정은 TensorRT 엔진 빌드와 카메라 버퍼 할당을 직접 시도해 확인한다(§5 #1).

### C-3. 25W 고정 — MAXN SUPER 미적용

67 TOPS·GPU 1020 MHz는 mode 2 기준이므로 현재 설정은 최대 성능이 아니다. tj 45.4 °C, VDD_IN 3.3 W로 열·전력 헤드룸은 크다.

- 대응: 25W와 MAXN SUPER 양쪽에서 벤치마크를 돌려 FPS 대비 tj·VDD_IN을 비교하고 운용 모드를 확정한다. 모드 변경은 재부팅이 필요하고, MAXN SUPER는 전원 어댑터 용량을 먼저 확인해야 한다.
- 선박은 밀폐·고온 환경이 될 수 있다. 탁상 45 °C가 실환경 헤드룸을 보장하지 않는다. 케이스에 넣은 상태로 재측정한다.

### C-4. Jetson 루트가 microSD — 모델 I/O 병목과 쓰기 내구성

NVMe가 없어 모델 로드, 데이터셋 접근, 로그 기록이 모두 SD를 지난다. 개발 키트의 M.2 Key M 슬롯에 **NVMe SSD 이전을 권장**한다. 우선순위 상. 최소한 모델·엔진 파일만이라도 옮긴다.

### C-5. Pi 5 유휴 64.2 °C — 헤드룸이 좁다

부하 없이 64.2 °C다. 공식 팬 커브가 50 °C 30% / 60 °C 50% / 67.5 °C 70% / 75 °C 100%이므로 유휴에 이미 50% 구간이다. `throttled=0x0`이라 이력은 없지만, 브로커·SQLite·프레임 수신이 동시에 돌면 상승 폭을 예측할 수 없다.

- 대응: 액티브 쿨러 확인·장착. 부하 시험 중 `vcgencmd measure_temp`·`get_throttled` 주기 기록. 전원 5V/5A(27W) PD 권장 — 부족하면 USB 주변장치 전류가 제한된다. 서보 전원은 별도 계통이다.

### C-6. 시간 기준 — 사고 시각의 신뢰성

Pi 5는 RTC 백업 배터리가 없으면 전원 차단 후 시각이 틀어진다. 온보드 ERD의 `pi_accident.created_at`은 Unix 시간 int이고, 스테레오·IMU 융합도 시간 동기를 전제한다.

- 대응: 두 보드 NTP 동기. 인터넷이 없는 운항 중에는 Pi를 기준 시계로 두고 Jetson이 맞추는 구성, 또는 Pi에 RTC 모듈 추가. 사고 기록 기능 구현 전에 확정한다.

### C-7. 두 보드 연결 구성이 서술과 어긋난다

`127.0.0.1/21`과 `127.0.0.1/21`은 같은 /21 안에 있어 통신은 성립하지만, 공인 IP 대역의 /21은 캠퍼스망 할당 주소로 보인다. 전용 직결 링크라면 통상 사설 /30이나 link-local을 쓴다.

지금 구성이 캠퍼스 스위치를 경유하는 것이라면 "Wi-Fi·인터넷이 끊겨도 탐지·경보·발사 경로가 유지된다"는 설계 목표가 성립하지 않는다.

- 대응: `ip route`, `ip neigh`, 케이블 물리 경로를 확인한다. 직결 운용이 목표라면 별도 NIC에 사설 /30(예: `192.168.99.1/30`, `192.168.99.2/30`)을 고정 배정한다. **확정 대기.**

### C-8. 사고 후 영상 1시간 — Pi 저장·업로드 대역

사고 후 영상 보관이 **최대 1시간**으로 확정됐다(팀 결정 2026-09-10). 5 fps × 3600 초 = 18,000장이다.

| 항목 | 값 |
|---|---:|
| 사고 1건 tar | 125장 · 약 25 MB (앞 15초 + 뒤 10초, 장당 200 KB 가정) |
| 생성 주기 | 30초마다 1개 |
| **필요 업로드 대역** | **약 0.5 MB/s = 4 Mbps 지속** |
| 사고당 총량 | 약 1.8 GB |

- 시연 환경에서 인터넷이 보장되므로(팀 결정 2026-09-10) **오프라인 백로그 대책은 범위 밖이다.** fps 저감이나 디스크 대기열을 두지 않는다.
- 30초 단위로 묶어 전송하고 **업로드 확인 후 삭제**한다. 정상 상태에서 디스크에 tar 1~2개만 남으므로 microSD 29.2 GB 용량은 문제되지 않는다.
- 상시 녹화는 RAM 링버퍼(IOT-09)이므로 평상시 디스크 쓰기가 없다. **쓰기 내구성은 사고 시에만 발생하며 시연 규모에서 제약이 아니다.**
- 구현 주의: 업로드 요청 전송 시점이 아니라 **저장 확정 응답을 받은 뒤** 삭제한다. tar는 임시 이름으로 쓰고 완성 후 rename 해 부분 파일이 업로드되지 않게 한다.
- tar는 압축이 아니다. JPEG는 이미 압축돼 있어 gzip으로도 줄지 않고, 파일당 512바이트 헤더·패딩이 붙는다. 용량을 줄이려면 fps·해상도·JPEG 품질만이 수단이다.
- 장당 100 KB는 가정값이다. 해상도가 가장 큰 변수이므로(1280×720 q85 약 80~150 KB, 640×480 약 35~60 KB) 실제 장당 바이트를 먼저 측정한다.

## 4. 카메라 구성

| 항목 | 값 | 상태 |
|---|---|---|
| 수량 | **2대** (스테레오) | 확정 — 노션 2.2 |
| 방향 | 선박 후방 해상 | 확정 |
| 모델 | 미확정 — 랩실 웹캠 불출 요청 중 | |
| 동일 모델 | **필수** | 스테레오 캘리브레이션 조건 |

현재 영상 파이프라인 구현은 USB 1대(`/dev/video0`, 5 fps)이므로 **구현이 설계를 아직 따라오지 못한 상태**다. 설계 불일치가 아니라 구현 진행 단계 차이다.

스테레오 거리·방위 계산이 이 문서의 추론 부하 전제에 포함돼 있으므로, 카메라 모델이 확정되기 전에는 §5 #3·#5 결과를 신뢰할 수 없다. 장착 위치·기선은 [DES-36 §3](IoT_REVIEW_DES-36_선박장착.md)에서 다룬다.

## 5. 검증 계획 (②·③ 파트의 입력)

| # | 측정 항목 | 조건 | 기록값 |
|---:|---|---|---|
| 1 | 헤드리스 전환 효과 | GUI 제거 전/후 | `free -h` 가용량, `lfb`, 엔진 빌드 성공 여부 |
| 2 | 전원 모드별 성능 | 25W vs MAXN SUPER | FPS, tj, VDD_IN, GR3D% |
| 3 | 정밀도별 성능 | FP16 vs INT8 | FPS, mAP50, Recall |
| 4 | 스토리지 영향 | microSD vs NVMe | 모델 로드·엔진 빌드 시간 |
| 5 | 카메라 대역 | USB 스테레오 2스트림 동시 | 실효 FPS, 프레임 드롭, USB 오류 |
| 6 | 엔진 오프로드 | VIC/NVDEC 사용 전/후 | GR3D% 변화 |
| 7 | Pi 5 부하 내열 | 브로커+SQLite+프레임 수신 | `measure_temp`, `get_throttled` |
| 8 | 케이스 내 열 | 밀폐 30분 | tj 추이, 스로틀 여부 |
| 9 | 보드 간 통신 | 지연·단절 주입 | 상태 전이 지연, 타임아웃 동작 |

Recall과 False Negative를 Precision보다 우선 관리한다는 팀 기준을 적용한다.
